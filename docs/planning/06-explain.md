> 과제 목표: 시계열 요약·컨텍스트 주입, 라우터/서비스 분리, Pydantic 검증, Firestore CRUD, CORS·환경변수·키 관리를 **우리 코드로** 설명할 수 있다.

## 0. 컨텍스트 주입의 원리
- GPT는 내 학습 기록을 모른다. 요청마다 이전 요청도 기억하지 못해서 **매번 보내는 메시지 목록에 들어 있는 것만 안다.**
- 그래서 서버가 질문이 올 때마다 요약을 새로 만들어 맨 앞 `system` 메시지에 글로 넣는다. 이것이 **컨텍스트 주입**이다. (`chat_service.build_system_prompt`)
- GPT에게 가는 메시지 모양(예시):

```
[system]  당신은 영어 단어 암기 앱 '스포카'의 학습 코치입니다. 한국어 존댓말로 답하세요.
          아래 '학습 기록 요약'의 수치만 근거로 답하고, 요약에 없는 내용은 추측하지 마세요. …

          [학습 기록 요약] (오늘: 2026-10-06, 한국 시간)
          - 전체(…): 기록한 날 112일, 하루 평균 7.1개, …
          - 최근 7일(오늘 포함)(2026-09-30 ~ 2026-10-06): 기록한 날 7일, 하루 평균 9.9개, 최대 15개, 최소 2개
          - 직전 7일 하루 평균: 10.0개
          - 추세(직전 7일 평균 대비): 유지
          - 최근 7일 날짜별 외운 단어 수: · 2026-09-30: 7개 · 2026-10-01: 14개 · …
[user/assistant]  (지난 대화들)
[user]    최근 7일 어땠어?
```

- 포인트 3가지
  1. **원본 대신 요약**: 112일치 기록을 통째로 보내면 느리고 비싸고 GPT가 헷갈린다. 계산은 서버가 정확하게, GPT는 말로 풀어 주는 역할만.
  2. **추측 금지 문장**: "요약에 없는 건 모른다고 말하라"고 시켜 수치 지어내기를 막는다.
  3. **한계는 도구로 보완**: 요약에 없는 날짜·기간은 보너스 5.1의 도구(`get_records` 등)로 그때그때 조회한다.

## 1. 시계열 → 요약 → 활용 흐름

```
0 기록 쌓기        Firestore `data` (날짜별 외운 단어 수)
        │
1 질문 받기        POST /api/chat
        │
2 요약 만들기      summary_service: 전체 + 최근 7일(개수·평균·최대·최소·추세·날짜별 값)
        │
3 프롬프트 삽입    system 메시지에 요약을 글로 넣음
        │
4 GPT 호출         system(요약) + 지난 대화 + 질문   (필요하면 도구 호출 최대 3번)
        │
5 답변 저장        Firestore `conversations` (질문·답변·조회한 도구 표시)
        │
6 화면 표시        수치가 반영된 답변
```
- 요약은 저장해 두지 않고 **질문 때마다 새로 계산**한다 → 방금 추가한 기록도 바로 반영된다.
- 같은 요약을 요약 카드, 리포트, AI코치가 함께 쓴다.

## 2. 라우터와 서비스를 나누는 기준
기준은 하나: **"HTTP를 몰라도 되는 일인가?"** 그렇다면 서비스, 아니면 라우터.

| 물음 | 라우터 (`routers/`) | 서비스 (`services/`) |
| --- | --- | --- |
| HTTP를 아나? | 예 (주소, 방식, 상태 코드) | 아니오 |
| 하는 일 | 요청 받기 → 서비스 호출 → 응답 만들기 | 규칙·계산·저장·AI 호출 |
| 예 | `POST /api/data`가 201 반환, 중복이면 409로 변환 | 같은 날짜 검사, Firestore 저장 |
| 오류 | 예외를 HTTP 상태 코드로 변환 | `DuplicateDateError` 같은 앱 예외를 던짐 |
| 다른 곳에서 재사용 | 안 됨 | 됨 (GPT 도구, MCP가 같은 함수를 사용) |
| 시험 | 서버를 띄워 요청을 보내야 함 | 함수만 불러 값을 확인하면 됨 |

비유: 서비스 함수는 "일을 하는 사람", 라우터 함수는 "창구 직원". 앱 안의 GPT와 MCP는 창구를 거치지 않고 일하는 사람을 바로 부른다.
함수(`data_service.create()`)는 서버 안에서만 부를 수 있고, API(`POST /api/data`)는 그 함수를 인터넷 주소로 열어 주는 문이다. 주소·방식·응답 모양·오류 코드를 정하는 곳이 라우터 함수다.

### FastAPI란
라우터를 쉽게 만들어 주는 파이썬 웹 프레임워크(타입 힌트 + Pydantic 기반).

| FastAPI가 해 주는 일 | 우리 코드에서 |
| --- | --- |
| 주소·방식 연결 | `@router.post("")`, `prefix="/data"` → `POST /api/data` |
| 입력 자동 검사 (Pydantic 연동) | 인자 `payload: DataCreate` → 틀리면 422 자동 |
| 응답 모양 보장 | `response_model=DataOut`으로 정해진 필드만 응답 |
| 자동 문서 | `/docs`(Swagger)에서 바로 실행 가능 |
| 여러 요청 동시 처리 | 동기 함수를 여러 스레드에서 실행 |
| 공통 처리 | CORS 미들웨어, 오류를 `{"detail": …}` 한 가지로 통일 |

## 3. 요청이 지나가는 길 (`POST /api/data` 예)
```
브라우저 ──▶ 라우터(routers/data.py) ──▶ 스키마(schemas/data.py, Pydantic) ──▶ 서비스(data_service.py) ──▶ Firestore
                                              │ 실패: 422 입력이 틀림              │ 실패: 409 같은 날짜 있음
```

## 4. 왜 JS 검증이 있는데 Pydantic을 또 쓰나
- **JS 검사 = 사용자 안내용**: 서버까지 가지 않고 바로 "날짜를 확인해 주세요"라고 알려 준다. 빠르고 친절하지만 건너뛸 수 있다.
- **Pydantic 검사 = 데이터를 지키는 최종 문지기**: 브라우저 개발자 도구, Swagger(`/docs`), curl, 다른 앱, MCP 등은 JS를 거치지 않고 서버에 바로 요청한다. 서버가 검사하지 않으면 `value: -5`나 없는 날짜가 DB에 들어가고 요약·통계·AI 답변이 모두 틀어진다.
- 원칙: **클라이언트 검사는 편의, 서버 검사는 필수.** 하나만 둔다면 서버.
- 부가 장점: 규칙을 한 곳(`schemas/data.py`)에 선언하면 검사·오류 메시지·Swagger 문서가 같이 생긴다.
- 우리 규칙: date `YYYY-MM-DD` + 실제 있는 날짜(`field_validator`), value 0 이상 정수(strict), memo 200자 이하.

## 5. Firestore CRUD와 GET/POST/PUT/DELETE

| 일 | HTTP | 경로 | Firestore 동작 (`data_service.py`) | 성공 응답 |
| --- | --- | --- | --- | --- |
| 만들기(Create) | `POST` | `/api/data` | 같은 날짜 검사 후 `add(...)` (문서 ID 자동) | 201 |
| 읽기(Read) | `GET` | `/api/data` | `order_by("date")`, 기간 `where`, `limit+1`로 다음 페이지 확인 | 200 |
| 고치기(Update) | `PUT` | `/api/data/{id}` | 있는지 확인 → 날짜 겹침 검사 → `set(...)`으로 **통째로 교체** | 200 |
| 지우기(Delete) | `DELETE` | `/api/data/{id}` | 있는지 확인 → `delete()` | 204 (내용 없음) |

- **GET**: 읽기만, 데이터를 바꾸지 않음. 몇 번 불러도 결과가 같다.
- **POST**: 새로 만들기. 같은 요청을 두 번 보내면 두 개가 생길 수 있어서 날짜 중복 검사로 막는다.
- **PUT**: "이 자료를 이 내용으로 통째로 바꿔라". 날짜·값·메모를 모두 보낸다. 일부만 바꾸는 건 PATCH(우리는 사용 안 함).
- **DELETE**: 삭제. 없는 ID면 404.
- 구조: `data`는 컬렉션(폴더), 기록 하나는 문서(파일), 문서 ID는 Firestore가 자동 생성.
- Firestore는 "날짜는 하나만" 같은 제약을 걸지 못하므로 서비스가 저장 전에 `date`로 먼저 찾아 본다.
- "더 보기"는 마지막 날짜를 `cursor`로 받아 그 이전 기록을 이어서 읽는 방식.
- 오류 코드: 404(없는 기록), 409(같은 날짜), 422(입력 오류), 502(GPT 실패).

## 6. CORS · 환경변수 · 키 관리
```
브라우저 화면(키 없음) ──▶ FastAPI(Render, CORS: 허용 주소만) ──▶ Firestore(서비스 계정 키)
                                   ▲                      └─▶ 교육장 GPT(API 키)
                          환경변수(.env·Render)에만 키를 둠   GitHub에는 .env 올리지 않음
```
- **키는 서버 환경변수에만**: OpenAI·Anthropic 키, Firestore 서비스 계정 키는 코드, GitHub, 브라우저에 두지 않는다. 브라우저에 있으면 누구나 꺼내 쓸 수 있다. `.env`는 `.gitignore`로 막고, 배포에서는 Render 화면에 직접 입력한다.
- **환경변수의 이점**: 코드를 바꾸지 않고 로컬/배포 값을 다르게 쓸 수 있다. (`core/config.py`에서 한 곳으로 읽음)
- **CORS**: `ALLOWED_ORIGINS`에 적은 프론트 주소(로컬 + Vercel)에서 온 요청만 브라우저가 받도록 서버가 알려 주는 장치. 다른 사이트의 스크립트가 내 API를 부르는 것을 막는다.
- 주의: CORS는 브라우저에서만 작동하는 안전망이다. 키 보호가 더 근본적인 방어다.

## 7. 한 줄 요약 (발표용)
1. 기록을 시계열로 쌓고, 질문 때마다 **요약을 새로 계산해 system 프롬프트에 넣어** GPT가 내 수치로 답한다.
2. HTTP를 아는 일은 **라우터**, 앱 규칙은 **서비스**, 입력 검사는 **Pydantic 스키마**.
3. JS 검사는 편의, **서버 검사는 필수**.
4. CRUD = POST/GET/PUT/DELETE ↔ Firestore `add`/`query`/`set`/`delete`.
5. 키는 환경변수에만, 접근은 CORS로 허용 주소만.
